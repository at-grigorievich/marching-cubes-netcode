# Как проверять: Unity в облачной сессии, прогоны, тесты, сборка

Пользователь работает в редакторе на Windows и гоняет прогоны через `unity` CLI
(`CLAUDE.md`, «Чем проверять»). Исполнитель плана работает в **облачном контейнере Linux**,
где редактора нет, пока его не поставить. Ниже — что там работает и что нет. Всё,
кроме ветки с лицензией, **проверено в облачной сессии** (октябрь 2026).

---

## Два уровня проверки

| уровень | что нужно | что проверяет | время |
|---|---|---|---|
| **1. Компиляция** — `Tools/CloudUnity/compile_check.py` | редактор (без лицензии) | все сборки проекта: Assembly-CSharp, Assembly-CSharp-Editor, asmdef в `Assets`; **два прохода**: как в редакторе и как в выпускной сборке WebGL | первый раз ~2.5 мин, дальше ~25 с |
| **2. Прогоны и тесты** — `Tools/CloudUnity/run-unity.sh` | редактор + **лицензия** | всё из `CLAUDE.md`, «Чем проверять»: `CatacombRunCheck`, `CatacombCrowdCheck`, … + EditMode-тесты + сборка WebGL | минуты; первое открытие проекта — импорт ассетов |

**Уровень 1 обязателен перед каждым коммитом.** Уровень 2 — перед закрытием задачи, где
меняется поведение (всё в M0–M3), и всегда, когда задача называет прогон в критериях.

## Установка

```bash
bash MarchingCubes-Netcode/Tools/CloudUnity/setup-unity.sh           # редактор ~4.1 ГБ, ~3–5 мин
bash MarchingCubes-Netcode/Tools/CloudUnity/setup-unity.sh --webgl   # + модуль WebGL ~1.3 ГБ (для M5)
```

Ставит редактор версии из `ProjectSettings/ProjectVersion.txt` в `/opt/unity-<версия>`
и ссылку `/opt/unity`. На диске ~8 ГБ редактор и ~3 ГБ модуль WebGL. Нужна сеть
до `download.unity3d.com` (и `packages.unity.com` / `download.packages.unity.com` для
пакетов, которых нет в поставке редактора) — в среде с ограниченной сетью эти хосты
надо разрешить.

Чтобы не ставить руками каждую сессию, пользователь может добавить вызов в **скрипт
настройки среды** (настройки облачной среды → Edit → Setup script).

## Уровень 1: проверка компиляции без лицензии

```bash
python3 MarchingCubes-Netcode/Tools/CloudUnity/compile_check.py               # оба прохода
python3 MarchingCubes-Netcode/Tools/CloudUnity/compile_check.py --player-only # только «как WebGL»
```

Скрипт повторяет конвейер компиляции Unity: пакеты — ровно версии из `packages-lock.json`
(из поставки редактора, недостающие докачиваются), их asmdef собираются Roslyn из поставки
по порядку зависимостей, потом проектные сборки. Код возврата 0 — проект компилируется.

* **Проход «плеер WebGL»** собирает рантайм без `UNITY_EDITOR`, без ссылок на `UnityEditor`,
  против плеерных сборок движка из модуля WebGL (если он стоит) и с define выпускной сборки
  (без `ENABLE_UNITY_COLLECTIONS_CHECKS`, `DEBUG`). **Он ловит грабли №6** — на первом же
  запуске нашёл `ChunksWeightEditorTool.cs`, ломавший сборку WebGL (`CLAUDE.md`, грабли №68).
* Ошибки в сборках **пакетов** печатаются строкой `~ пакет …` и код возврата не портят.
  Сейчас так падают только ILPostProcessor-сборки (`*.CodeGen`), экспериментальный
  `com.unity.pipeline` и `Unity.VisualStudio.Editor` — проекту они не нужны.
* Чего он **не** делает: не запускает код, не делает Burst-компиляцию и ILPostProcessing,
  не компилирует шейдеры. Зелёная компиляция — не «работает», а «собирается».

Две особенности Unity 6000.4, которые скрипт повторяет и которые стоит знать (подробно —
в комментариях скрипта):

* uGUI и TextMeshPro (`com.unity.ugui`) видны **всем** сборкам без ссылки в asmdef.
* ShaderGraph пишет голое `GUID`, а тип теперь только `UnityEngine.GUID` — для этой
  **пакетной** сборки подставляется `global using`. Проектные сборки вставок не получают.

## Уровень 2: прогоны с лицензией

### Лицензия — делает пользователь

Без лицензии редактор в batchmode отвечает «No valid Unity Editor license found»
и проект не открывает. Варианты (секреты среды, в чат их не присылать):

| переменная | откуда |
|---|---|
| `UNITY_LICENSE` | содержимое файла `Unity_lic.ulf` с машины, где Unity активирован: Windows — `C:\ProgramData\Unity\Unity_lic.ulf`. Способ GameCI для Personal |
| `UNITY_SERIAL`, `UNITY_EMAIL`, `UNITY_PASSWORD` | для Plus/Pro: активация серийным номером |

`setup-unity.sh` при наличии переменных записывает лицензию / активирует. **Эта ветка
в облаке не проверена** — при первом запуске смотреть лог.

### Запуск

```bash
R=MarchingCubes-Netcode/Tools/CloudUnity/run-unity.sh
bash $R method MineGenerator.Catacombs.EditorTools.CatacombRunCheck.Run    # полное имя — грабли №18
bash $R method MineGenerator.Catacombs.EditorTools.CatacombCrowdCheck.Run
bash $R tests                                                               # EditMode-тесты, отчёт XML
```

Код возврата 3 — нет лицензии. После прогона скрипт печатает `git status`: Unity может
тронуть `UserSettings/` и `ProjectSettings/` — **не коммитить это без причины**. Прогоны,
которые **сохраняют сцену** (`CatacombBatchCheck`, `CatacombSceneRefresh`), меняют
`Assets/Scenes/*.unity` — коммитить только если это и было целью (грабли №25, №30, №67).

Прогоны, снимающие **кадры** (`CatacombBatchCheck`), требуют графики: `UNITY_WITH_GRAPHICS=1`
запускает через `xvfb-run` без `-nographics`. В контейнере без GPU это программная
отрисовка — **не проверено**, работает ли она с URP Forward+; если нет — кадры снимает
пользователь у себя, числовые прогоны всё равно идут.

## Правила для новых прогонов (из `CLAUDE.md`)

* У каждого прогона две точки входа: `Run()` — для batchmode, кончается
  `EditorApplication.Exit` с кодом; `Report()` — для вызова из открытого редактора, редактор
  не закрывает (грабли №26), возвращает текст отчёта строкой (грабли №40).
* Прогон **сам** ставит игрока на точку входа и сам пересоздаёт компоненты с умолчаниями
  из кода, а не берёт из сохранённой сцены (грабли №8, №30).
* Числа меряются на трёх сидах минимум (грабли №13), хаотичные метрики усредняются (№24),
  база берётся прямо перед событием (№28), игрок с ограниченным уроном (№45).
* Полное имя для `-executeMethod`: `MineGenerator.Catacombs.EditorTools.<Класс>.Run`.

## Новые прогоны по вехам

| прогон | веха | что меряет |
|---|---|---|
| `SurvivalCheck` | M1 | укусы, потолок урона, время до смерти, рывок, «толпа держит» |
| `UiCheck` | M1 | экраны создаются, ключи локализации есть, ноль аллокаций HUD |
| `WeaponCheck` | M2 | форма поражения каждой пушки, сквозь стенку не бьёт, атрибуция, DPS-таблица |
| `SpecialsCheck` | M3 | расписание особых, вне поля зрения, их действия, парирование |
| `RecipeCheck` | M4 | рецепты уровня: связность, тупики, зал логова, время генерации, память |
| `SaveCheck` | M4 | профиль и снимок забега туда-обратно |
| `ProgressionSim` | M6 | боты трёх профилей по ярусам, целевые окна баланса |
| `WebGLBuildCheck` | M5 | сборка WebGL по профилю площадки: размеры (начальная загрузка, всего, файлов), топ ассетов, имена файлов |

`WebGLBuildCheck` пишется в M5: `BuildPipeline.BuildPlayer` в `/opt/unity-work/build/<профиль>`
(вне репозитория), разбор `BuildReport`, проверка порогов из `M5-platforms-mobile.md`.
Требует модуль WebGL и лицензию.

## EditMode-тесты

Папка `Assets/Tests/Editor/` без asmdef — тесты попадают в `Assembly-CSharp-Editor`
и видят игровой код (проектных asmdef нет). `compile_check.py` даёт этой сборке NUnit
и тест-раннер так же, как Unity. **Проверить на первом же тесте**, что Test Runner их видит
(`run-unity.sh tests`, в XML есть тест); если нет — завести asmdef для игрового кода
(это большая правка, согласовать с пользователем).
