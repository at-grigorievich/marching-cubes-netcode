# Процедурные катакомбы

Рантайм-генератор многоуровневых подземелий на Marching Cubes. Всё настраивается
через ScriptableObject `Catacomb Settings`, геометрия строится в Burst-джобах
с бюджетом по кадрам, порода копается в рантайме.

## Быстрый старт

1. `Tools → Mine Generator → Создать тестовую сцену` — соберёт ассет настроек,
   материал породы с текстурой, объект `Catacombs`, игрока со светом и туманом.
2. **Play**, клик по окну игры. ЛКМ — копать, ПКМ — зарастить, **F** — полёт/ходьба,
   **T** — к точке входа, **R** — новый уровень, **G** — полёт сквозь стены.

Полёт по умолчанию упирается в породу так же, как ходьба. Если камера всё-таки окажется
внутри стены, кадр станет чёрным: обратные грани отсекаются, и видно цвет очистки камеры.
Это не дыра в геометрии — меш герметичен.

Без Play: выделите `Catacombs` и нажмите **«Сгенерировать»** — уровень построится
прямо в Scene view. Чанки помечены `HideFlags.DontSave`, в сцену они не сохраняются.

Только настройки без сцены — `Tools → Mine Generator → Создать сетап катакомб`.

Если картинка не похожа на ожидаемую — скорее всего в ассете настроек остались значения
от прошлой версии генератора. Поля, совпавшие по имени, переживают обновление, и старая
мягкость края со старым шумом размывают коробки обратно в бесформенные ходы. Лечится
пунктом `Tools → Mine Generator → Настройки как на рендере` или кнопкой в инспекторе
`Catacombs` — она появляется сама, когда ассет устарел.

## Как это устроено

```
CatacombLayout      планировка: залы, коридоры, лестницы — набор SDF-примитивов
      |             (main thread, доли миллисекунды)
      v
CatacombDensityJob  поле плотности чанка из SDF + шум  (Burst, IJobParallelFor)
      |
      v
MarchingCubesJob    полигонизация со склейкой вершин   (Burst, IJob)
      |
      v
CatacombChunk       Mesh + MeshCollider
```

**Один примитив на всё** — параллелепипед со скруглёнными рёбрами (`CaveBox`).
Залы, коридоры, площадки и наклонные пролёты отличаются только габаритами и поворотом.
Капсулы, с которых начиналась первая версия, давали «кишки»; прямоугольник со
скруглением читается как рукотворный ход.

**Планировка.** Уровень — это сеть узких ходов между небольшими узлами-развилками,
а не анфилада залов. Узлы раскладываются по дрожащей сетке и выравниваются по `Grid Step`,
связываются остовным деревом (оно гарантирует проходимость) плюс лишние рёбра для колец.
Коридоры идут строго по осям и поворачивают под прямым углом.

**Тупиков не бывает.** У остовного дерева листья это и есть тупики, а в игре про толпу
тупик — смерть без контригры. Поэтому после построения графа идёт проход, добирающий
связи узлам со степенью ниже `Min Connections`. Замер на пяти сидах: тупиков 0,
развилок в среднем 3.1–3.3 на узел.

Если кайтить окажется негде, поднимите `Arenas Per Level` до 1 — столько узлов на этаже
расширится до арены. По умолчанию 0: сплошная теснота.

**Спуски.** Голова лестницы выносится за стену зала, дальше идёт серпантин с
площадками на разворотах. Крутизна ограничена `Ramp Slope` явно, вертикальных
шахт не бывает: при `Ramp Slope 0.5` фактический максимум по всем пролётам — 26.4°.

**Плотность.** `> IsoLevel` — пустота, `< IsoLevel` — порода. По краю мира плотность
принудительно занулена на толщину `Boundary Thickness`, выкопаться наружу нельзя.

**Швы.** Соседние чанки считают общий пограничный слой сэмплов по одним и тем же
мировым координатам, поэтому значения совпадают и щелей не возникает. Плюс в каждом
чанке есть кольцо запаса в один сэмпл — по нему считаются нормали (градиент плотности),
так что и освещение на границе не рвётся. Проверено: 0 открытых рёбер на 78 тысяч.

## Материал

У меша Marching Cubes нет UV, поэтому обычная текстура на него не ляжет. Шейдер
`Mine Generator/Cave Triplanar` кладёт её тремя мировыми проекциями и отдельно
подмешивает оттенок по наклону: пол светлее, потолок темнее. Именно это даёт
читаемость объёма — одного точечного источника в позиции камеры для этого не хватает,
там `N·L` почти постоянна и картинка вырождается в плоскую заливку.

**Про положение фонаря.** Смещать источник от камеры нельзя почти никак. Боковой вынос
делает стену сбоку от игрока обратной стороной к фонарю (`N·L < 0`), и она чернеет;
вынос вперёд не лучше — стена ближе выноса оказывается у фонаря за спиной. Перебор
1199 ракурсов вплотную к стенам: вынос `(0.9, 0.7, 0)` дал 216 кадров, где черно больше
пятой части экрана, вынос `(0, 0.12, 0)` — ни одного. За объём отвечает оттенок по наклону,
а не смещение фонаря. Плюс `_MinLight` в материале держит нижний порог освещённости,
чтобы отвёрнутая от света поверхность не уходила в чистый чёрный.

Текстура `Assets/Textures/Cave Rock.png` генерируется процедурно и бесшовна.
Замените её на свою — шейдер возьмёт любую. `Tools → Mine Generator → Пересоздать
материал породы` пересобирает и текстуру, и материал.

## Копание

```csharp
[SerializeField] private CatacombWorld world;

world.Dig(hit.point, radius: 4f, strength: 1f);      // взрыв гранаты
world.Dig(hit.point, radius: 1.5f, strength: 0.6f);  // кирка
world.Fill(point, radius: 3f, strength: 1f);         // обвал
```

Кисть подтягивает поле к SDF сферы, а не доливает плотность. Иначе при силе 1
`saturate` забивает всю сферу ровной единицей: внутри плато с нулевым градиентом,
переход к породе в один воксель, и каверна выходит из плоских граней по сетке.
Побочный эффект новой схемы полезный — повторный удар в то же место ничего не меняет,
так что кирка требует смещаться.

**Радиус кисти не должен быть меньше вокселя.** Кисть 0.5 при `Voxel Size 1` не задевает
ни одного сэмпла сетки: 35 ударов подряд не меняли ни одного треугольника. Стенд
ограничивает минимум значением `VoxelSize * 1.2`.

`Dig` возвращает `true`, если задел хоть один чанк. Перестройка мешей идёт в
`LateUpdate` с бюджетом по кадрам, поэтому очередь взрывов не роняет фреймрейт.

Для подсчёта добытого ресурса удобно считать объём `4/3 · π · r³ · strength`
либо сравнивать сумму плотностей до и после (`chunk.Density`).

## Настройки

| Параметр | Смысл |
|---|---|
| `Chunk Resolution` | ячеек на сторону чанка. 16 — рабочая точка, 32 дороже вчетверо |
| `Voxel Size` | размер ячейки в юнитах, он же предел детализации |
| `World Size In Chunks` | размер мира. Итог в юнитах = `Resolution × VoxelSize × ChunksCount` |
| `Boundary Thickness` | толщина сплошной породы по краю мира |
| `Grid Step` | шаг планировочной сетки — от него зависит «рукотворность» уровня |
| `Level Count` | этажей. Если по высоте не влезают, генератор урежет и предупредит |
| `Rooms Per Level` | узлов-развилок на этаже (диапазон) |
| `Room Size` / `Room Height` | габариты узла. Это перекрёсток, а не зал |
| `Arenas Per Level` / `Arena Scale` | сколько узлов расширить до арены и во сколько раз |
| `Min Connections` | минимум ходов из узла. 2 и выше — тупиков нет |
| `Corridor Width` / `Height` | сечение коридоров |
| `Extra Connections` | доля лишних связей сверх дерева — кольцевые маршруты |
| `Corner Rounding` | радиус скругления рёбер. 0 — острые углы |
| `Junction Blend` | сглаживание стыков. Больше 1 — углы начинают плыть |
| `Ramp Run` / `Ramp Slope` | длина пролёта и крутизна спуска |
| `Noise Amplitude` | фактура стен. 0 — идеально ровные плоскости |
| `Surface Softness` | ширина переходной зоны стены. Меньше — резче край |
| `Milliseconds Per Frame` | бюджет генерации на кадр. Для WebGL 4–8 |

## WebGL

В проекте `webGLThreadsSupport = 0`, воркеров нет — любой джоб доезжает на главном
потоке. Отсюда:

* `Milliseconds Per Frame` 4–8 плюс прогресс через `CatacombWorld.ProgressChanged`.
* Мир `6×4×6` чанков при `Resolution 16` — 144 чанка, 3.8 МБ плотностей,
  ~52 тысячи треугольников. Это разумный потолок.
* `Chunk Resolution 32` даёт вчетверо больше сэмплов на чанк — для веба берите 16.
* Инспектор предупредит, если плотности перевалили за 64 МБ.

Слишком маленький мир вырождается: при `3×2×3` чанков на `Resolution 8` помещается
ровно один зал. Ориентир снизу — примерно 80 юнитов по стороне.

## Замеры

Windows, редактор, Burst. Мир `6×4×6` чанков, `Resolution 16`, 3 уровня:
144 чанка, 29 500 вершин, 52 252 треугольника, 3.8 МБ плотностей.

Проверяется прогоном в batchmode: герметичность меша, совпадение плотностей на швах,
запечатанность границ, крутизна всех пролётов, отсутствие NaN и вырожденных
треугольников, реакция на копание.
